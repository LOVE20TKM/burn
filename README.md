# 销毁 LOVE20 生态资产，获得空投

> **当前状态：合约已实现，待部署校验与发布。**

Burn 是一个通用的 LOVE20 生态销毁合约。部署时指定一个范围代币，并显式配置本次支持的范围代币社区及已经完成发射的直接子币社区；参与者按销毁得分分配空投份额。

部署时还可以指定另一种 ERC20 作为空投代币，由参与者在销毁结束后直接领取；如果不指定，Burn 只计算最终份额，供外部空投程序使用。空投代币不能与范围代币相同。

这不是固定比例兑换。参与者获得多少份额，取决于社区权重、销毁类别、销毁得分和其他参与者的行为。

## 动态空投

`Airdrop` 可以把已结束 Burn 的全局最终份额固定为一份公开 Merkle 快照，并在任意 EVM 链按同一份额分配合约持有的标准 ERC20。每种代币独立领取，领取量按该代币当前余额和剩余未领取份额动态计算；详见[动态空投设计](./docs/airdrop-design.md)。

直接从来源网络生成快照并部署：

```bash
bash script/deploy/one_click_deploy_airdrop.sh <来源网络> <目标网络>
```

需要先审阅快照时，可分两步执行；部署命令会复用已生成快照：

```bash
SOURCE_BLOCK_NUMBER=<来源区块> bash script/deploy/generate_airdrop_snapshot.sh <来源网络> <目标网络>
bash script/deploy/one_click_deploy_airdrop.sh <来源网络> <目标网络>
```

每份快照、部署地址和验收清单都保存在自己的不可覆盖目录；广播后的验收失败可用同一命令重试，不会重复部署。

更新某网络当前可参与社区及 SL 中 LOVE20 数量的快照（默认写入 `burn.params` 注释，不改部署变量）：

```bash
bash script/deploy/00_prepare_config.sh <网络>
```

只检查链上结果是否与 `burn.params` 中的部署变量一致，不修改文件：

```bash
bash script/deploy/00_prepare_config.sh <网络> --check
```

## 哪些资产可以参与？

部署时配置的范围代币社区及已经完成发射的直接子币社区，可以使用以下四类资产参与：

- SL 流动性质押凭证：通过 Burn 转入对应社区代币合约并永久锁定。
- ST 加速质押凭证：通过 Burn 转入对应社区代币合约并永久锁定。
- 已实际铸造的治理激励代币：由 Burn 真实销毁。
- 已实际铸造的行动激励代币：由 Burn 真实销毁，包括部署时支持的扩展行动激励。

尚未铸造的理论激励、未配置或部署后新完成发射的直接子币，以及范围代币的孙币和更深层代币不能参与。治理激励额度按地址和轮次计算；行动激励额度按地址、轮次和每个行动分别计算，均以实际铸造激励为准。

社区代币合约持有的 SL/ST 余额表示该社区历史累计永久锁定量，可能包含误转或未通过 Burn 的主动转入；本次销毁获得计分的锁定量以 Burn 的查询和事件为准。

## 空投份额如何计算？

1. 每个社区的相对权重由部署参数传入并永久冻结，具体计算方法由该次部署决定。
2. 每个社区的份额按部署时冻结的四类资产权重分配。某类无人参与时，其份额按权重重新分配给该社区其他有参与的类别；当前参数可使用 `1:1:1:1`。
3. 同一社区、同一类别内，按每个地址的销毁得分分配。越早参与，得分系数越高。
4. 销毁期间看到的是实时预估份额；全部销毁轮次结束后，份额才最终确定。

## 一个简单例子

下面的数字只用于说明计算方式，不代表实际部署参数。

### 1. 社区权重

假设 Burn 部署时，三个参与社区传入的权重分别是 600、300、100：

```text
总权重 = 600 + 300 + 100 = 1,000
A 社区 = 600 / 1,000 = 60%
B 社区 = 300 / 1,000 = 30%
C 社区 = 100 / 1,000 = 10%
```

Burn 不会根据部署时的 SL、ST、流动性或价格修改这些权重。部署者可以自行选择计算方法，例如取最近七个完整轮次中 SL 所对应范围代币数量的中位数，但这不属于合约规则。

### 2. 类别和地址得分

假设四类权重为 `1:1:1:1`，A 社区获得全部份额的 60%，只有 SL 和治理激励两类有人参与：

```text
SL 类别份额      = 60% / 2 = 30%
治理激励类别份额 = 60% / 2 = 30%
```

地址得分等于锁定或销毁数量乘以当轮得分系数。越早参与，当前轮之后剩余的销毁轮数越多，系数越高；最后一轮的系数为 1。

假设某个社区代币的最大供应量为 100 亿，Burn 部署时已经铸造 10 亿，每轮治理和行动激励比例合计为 0.2%。小明在倒数第 11 个销毁轮次锁定 SL，即当前轮之后还有 10 个轮次：

```text
每轮参考激励 = (100 亿 - 10 亿) × 0.2% = 1,800 万
销毁得分复利基数 scoreBase = 1 + 1,800 万 / 10 亿 = 1.018
小明当轮得分系数 scoreMultiplier = 1.018 ^ 10 ≈ 1.195
最后一轮得分系数 = 1.018 ^ 0 = 1
```

小明在该轮锁定 100 个 SL，小红在最后一轮锁定 200 个 SL：

```text
小明得分 = 100 × 1.195 ≈ 119.5
小红得分 = 200 × 1 = 200

小明份额 = 30% × 119.5 / (119.5 + 200) ≈ 11.22%
小红份额 = 30% × 200 / (119.5 + 200) ≈ 18.78%
```

### 3. 激励销毁额度

假设小明某轮通过行动 A 实际铸造了 100 个行动激励代币，可销毁倍数为 5：

```text
行动 A 最多可销毁 = 100 × 5 = 500
已经销毁 120 后，行动 A 剩余额度 = 500 - 120 = 380
```

这里"可销毁"的是**社区代币**，而不是行动激励代币本身——额度由实际铸造的行动激励决定，但拿来销毁的代币可以来自小明的现有余额或市场购买，合约不追踪来源。

每个行动的额度单独计算。如果小明同轮还通过行动 B 实际铸造了 50 个激励代币，行动 B 会单独产生 `50 × 5 = 250` 的额度，不能与行动 A 的额度合并。尚未铸造的理论激励不会产生可销毁额度。

### 4. 空投代币领取

如果部署时指定了空投代币，每个地址按领取时的 Burn 余额和剩余未领取份额计算数量。

假设当前 Burn 持有 100,000,000 个空投代币，尚未领取份额为 100%，甲的最终份额为 20%：

```text
甲领取 = 100,000,000 × 20% / 100% = 20,000,000
```

甲领取后，Burn 还持有 80,000,000 个空投代币，剩余份额为 80%。如果此时又有人转入 10,000,000 个空投代币，乙的最终份额为 30%：

```text
乙领取 = 90,000,000 × 30% / 80% = 33,750,000
```

后续转入只会增加尚未领取地址的可领取数量，已经领取的地址不会补发。如果部署时没有指定空投代币，Burn 不提供领取功能，只提供最终份额。

## 参与前请注意

- 所有锁定和销毁都不可撤销，请确认数量后再提交。
- 每轮只能处理当前开放轮次，错过后不能补销毁，未使用额度也不会带到下一轮。
- 必须通过 Burn 提供的入口操作；直接转入 SL/ST 既不会获得得分，也无法取回。
- 直接向 Burn 转入已配置的空投代币会增加动态剩余池，不会获得销毁得分。
- 每个地址只能领取一次；领取数量以交易执行时的余额和剩余份额为准。
- 全部参与地址领取后的剩余资产无法取回。
